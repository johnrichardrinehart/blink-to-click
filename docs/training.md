# Automatic training and model selection

Gazeebo keeps one local training store. Users do not create, name, or select profiles. The store learns several operating contexts and chooses among them from camera observations and the portal-authorized display layout.

## Stored data

The versioned store lives below `$XDG_DATA_HOME/gazeebo`, or `$HOME/.local/share/gazeebo` when `XDG_DATA_HOME` is unset. Its directory is mode `0700` and its file is mode `0600`. Updates write a complete candidate to a sibling temporary file, synchronize it, replace the prior file atomically, and synchronize the directory. A malformed, unsupported, truncated, symlinked, or insecure store fails closed instead of being partly loaded. Compressed and expanded byte limits prevent hostile expansion.

The on-disk format is compact and lossless. It interns repeated camera, schema, output, topology, zone, and routing strings; stores numeric records as positional arrays; and compresses the canonical payload with a standard-library codec. It never quantizes, averages together, or removes distinct target aggregates. The deterministic 10,000-target fixture must average no more than 1 KiB per target on disk.

Each completed target contributes one record, even when its candidate model fails acceptance:

- the feature-schema version and an opaque camera fingerprint;
- one median feature vector combining required head/face geometry with optional pupil evidence and explicit aggregate pupil availability;
- one matching robust per-feature dispersion vector that summarizes active-window input noise without retaining observations;
- a context vector containing head pose, normalized face center and size, and frame luminance mean and spread;
- a generic output descriptor;
- the target's normalized position within that output and its center, edge, or corner zone;
- a fallback target position normalized to the source topology's bounding rectangle;
- an optional bounded cursor-noise summary containing only sample count, horizontal and vertical dispersion, covariance, median radial spread, and 95th-percentile radial spread;
- optional pre-incorporation median radial error, paired signed horizontal and vertical residuals, and median Bayesian posterior uncertainty for region-surprise scheduling and rough-in confidence sizing;
- a monotonic sequence number used for deterministic folds and references.

The store retains every historical target until explicit reset. It also contains bounded context-cluster metadata, serialized global and local estimator parameters, topology descriptors, aggregate validation results, and at most 64 accepted all-data model anchors. An anchor contains the final model refitted over every compatible historical and current target after folded selection and no-regression acceptance, plus aggregate posture/position/illumination context and validation metrics. It contains no session name or timestamp. The store never contains frames, images, raw landmarks, frame-level feature streams, preparation observations, invalid partial windows, per-frame prediction positions, personal names, device paths, or wall-clock usage history. Schema migration does not invent noise, surprise, or component-residual evidence for older targets. Schema nine adds optional paired signed residuals; schema-eight records retain their exact radial evidence without fabricated axes.

`gazeebo training-stats` reports schema version, target count, logical and on-disk bytes, compression ratio, and bytes per target as stable JSON. `gazeebo dump-training` expands the full store as stable, schema-labelled JSON on standard output. Both commands are read-only, require no camera or portal, and create no plaintext side file. `gazeebo reset-training` removes the store. Ephemeral operation neither reads nor writes it. Normal startup creates no target records; only completed initial or on-demand targets update the store.

False-negative evidence uses a different XDG archive and schema. It never appears in target records, model coefficients, `dump-training`, or `training-stats`. Capture is enabled by default and can be disabled by configuration or CLI. Each sustained warning stores lossless frames from the bounded three-second pre/post ring and finite detector metadata. `gazeebo diagnostic-stats` inspects quota use, and `gazeebo reset-diagnostics` removes validated owner-only event trees. The 2 GiB quota stops new events without deleting existing evidence.

## Rough-in confidence evidence

Each new target is predicted before incorporation. Gazeebo stores the signed difference between that pre-target prediction and the known target independently on the horizontal and vertical axes when both components are finite. The pair remains exact retained evidence; no decay, quantization, merging, eviction, or radial reconstruction changes it. Legacy radial error remains independently available.

At runtime one linear pass builds fixed-size component and legacy-radial histograms for the current camera and feature schema. Target topology mapping identifies the source output and scales each component by that output's current logical dimension. A confidence query uses the output-relative 3×3 cell only after its paired-component sample count reaches the configured minimum, then tries output and global components. If none qualifies, it tries region, output, and global radial evidence and uses a conservative square. Topology bounds are the final fallback. The full component dimensions are twice the conservative upper edge of the nearest-rank p99 histogram bin. Sparse levels never claim local p99 coverage.

Explicit finite width and height overrides replace the corresponding measured dimension. Every result reports its source, sample count, fallback or override, bounds clipping, and authorized-union intersection. These confidence summaries affect only rough-in presentation. They do not alter stored residuals, model fitting, the 100-pixel training gate, CVaR90 scheduling, or candidate acceptance.

## Display topology adaptation

The portal remains the authority for pointer access and logical geometry. A topology descriptor records each authorized region's opaque mapping identifier when available, logical size and position, and relative ordering. Exact topology identity uses the logical geometry rather than session-local portal IDs, so an unchanged layout can reload validated coefficients across authorizations. Target labels remain output-relative so resolution and position changes do not make every prior sample stale.

Gazeebo matches stored and current outputs in this order:

1. An unambiguous portal mapping identifier.
2. The same unique logical geometry despite a changed opaque identifier.
3. A unique logical-size and relative-neighborhood match.
4. No output match.

A strong match maps stored normalized targets and validated model predictions through their source output into the current region. This preserves the measured model's range on unchanged outputs when another output moves or scales. Gazeebo selects the best aggregate validation when old session-local IDs left more than one compatible coefficient set. If no validated coefficient set maps every current output unambiguously, Gazeebo refits remapped target labels. Removed outputs contribute no training samples, while validated predictions retain their mapping on every surviving output and use weak union-projected fallback only when a prediction belonged to the removed region. An added output has no local samples, but existing samples still fit the global and compatible context models over the current logical geometry. Samples without an unambiguous output match use their topology-bounds-normalized fallback label and are marked weak. Predictions always pass through authorized-union projection.

Exact and strong matches may report prior measured quality with its source topology. Weak matches report inferred, unvalidated quality. Logical geometry alone does not reveal physical display size, viewing distance, or real-world placement. Training sizing therefore uses physical dimensions only when an exact Wayland output match also supplies the selected current pixel mode; otherwise it uses the configured logical-pixel fallback.

Portal authorization and geometry are mandatory before pointer motion. A generic Wayland monitor refreshes available logical output geometry at a configurable one-second default cadence. Additions pause and renew portal authorization by default. Users may disable that pause, in which case additions remain outside the existing authorized union. Removed or reconfigured authorized geometry either renews authorization or stops motion; the setting never permits stale or unauthorized movement.

## Context vectors and clusters

Routing context excludes pupil coordinates so looking in a new direction does not itself select a different model. The context uses:

- head pitch, yaw, and roll;
- normalized face center, width, and height;
- frame luminance mean and standard deviation;
- the feature schema and opaque camera fingerprint as compatibility boundaries.

An online cluster stores a centroid, diagonal variance, sample count, validation quality, and references to its target aggregates. Distances use fixed dimension weights and variance floors. Assignment is deterministic: use the nearest compatible cluster within the configured distance, otherwise create a cluster. At the cluster limit, merge the closest compatible metadata or evict redundant metadata; neither operation deletes target records. No camera/schema partition can exceed eight active cluster descriptors.

Every compatible target contributes to the global or applicable context fit with a finite, strictly positive weight. Output, center/edge/corner zone, posture, illumination, pupil availability, and cursor noise inform folded selection and weighting. Noise can reduce a target's bounded weight but can never set it to zero. Incompatible topology records remain available for their matching topology or later remapping.

## Global and local estimators

The global fallback and local context experts reuse coefficient sets saved after folded model selection and no-regression acceptance. Each coefficient set may contain at most 32 output experts trained from that output's applicable records. The global prediction routes these experts from source logical geometry. Soft geometry weights blend neighboring outputs continuously; local predictions receive at most 80 percent total weight, so every compatible target retains positive influence through the global model. An output with fewer than three compatible records has no local estimator and gives its unavailable weight back to the global fallback. Exact-topology all-data model anchors become automatic context experts and interpolate through the same validation weighting, smoothing, and hysteresis as other accepted models. New and changed-topology fits use bounded direct and frozen-neural feature candidates; legacy stored RBF anchors remain readable but are never rebuilt from a sample-count-sized kernel. A final refit becomes an anchor only after current invocation targets provide acceptable pre-incorporation evidence. Output matching uses logical geometry rather than session-local portal IDs.

At startup Gazeebo gathers a short passive context window while portal geometry and model data finish loading. It scores compatible accepted experts and validated training anchors by current topology first, posture and camera geometry second, illumination third, and then real holdout quality. During navigation it refreshes output geometry before refreshing the camera-derived routing context at a configurable one-second default cadence. The router blends the best two with the accepted global estimator. Exponentially smoothed weights and a switching margin prevent model changes from jumping the cursor. An out-of-distribution context reports `training-recommended` rather than inventing measured accuracy.

General context mixtures use the accepted global estimator as their fallback. An anchor-only router instead uses the nearest real validated anchor when outside learned support; choosing the best aggregate anchor from an unrelated camera geometry caused camera repositioning to select the wrong transform. The route remains explicitly low-confidence until context returns to learned support.

Stationary cursor-noise evidence follows the same compatibility order: topology first, posture and camera geometry second, then illumination. A bounded weighted aggregate maps compatible 95th-percentile spread to finite dead-zone settings and, when configured, a lower smoothing alpha. The default alpha bounds are both 1.0, so navigation snaps to each rolling-median estimate instead of transiting toward it; users can lower the bounds explicitly. Runtime changes use the one-second context cadence and conservative parameter bounds. Fewer than 20 compatible active-window samples, an out-of-distribution context, or legacy evidence without summaries retains the documented fixed defaults instead of claiming noise adaptation or measured accuracy.

## Training transactions

A first run without usable training data enters initial training. `gazeebo train` requests training from an active foreground process through an owner-only Unix socket; if no process is active, it starts a foreground training session. There is no daemon.

Every requested invocation starts directly. Users may add evidence in their current posture, camera geometry, lighting, and output configuration; Gazeebo stores only aggregate unnamed context and later routes or interpolates it automatically.

One countdown appears on every authorized output before collection. Before each target, every output shows an eight-direction cue toward the target's global logical position. This lets a user find a circle that moved to another monitor. Labels report total invocation progress rather than restarting at each five-target batch. A terminal panel reports `collected / maximum` and distinguishes precision acceptance, a target-limit miss, interruption, and failure.

A target's configured millimetre diameter is converted independently for each output. The conversion requires an exact authorized-region match, physical dimensions from standard Wayland output geometry, and the selected current mode from `wl_output.mode`; other supported modes do not affect sizing. Missing or ambiguous metadata selects the user-configurable pixel fallback instead of guessing.

Every target starts with a two-second preparation phase by default. The next dot and a square with the same outer diameter appear while every output shows its directional cue. The prior dot overlaps and fades during the first second by default, then disappears while the square remains. Preparation ends when the square disappears and the dot becomes active. No observation is collected during preparation or overlap.

The active dot collects two seconds of reliable head/face measurement by default. Every reliable raw camera observation supplies head pose, normalized face geometry, available pupil evidence, context, and one estimated focal coordinate, independently of the lower pointer-emission cadence. Unseen error and the target noise distribution use these raw estimates. A separate 15-position median controls only the rendered cursor. Missing or unreliable pupils use the head/face-only estimator and never reset, retry, reject, or fail a target. Cursor noise is descriptive and never gates collection.

Loss of reliable head pose or face geometry pauses measurement and motion without discarding the partial target. A transient local full-camera view shows detected bounds, pose axes, a countdown, and corrective guidance. The diagnostic and pause remain for `--head-diagnostic-minimum` (3 seconds by default), including after quick recovery, so the message cannot merely flash. Recovery then resumes the same target automatically. Failure to recover within the separate configurable 10-second default ends training with a truthful panel. On acceptance, Gazeebo reduces the window to one median combined feature/context record, matching median-absolute-deviation feature dispersion, and a bounded cursor-noise summary, then drops all per-frame training values. Frames and landmarks inside an enabled sustained-warning event may remain only in the separate diagnostic archive and have no training influence.

A first run collects five deterministic seeds across authorized outputs to establish a finite model. Every later target is scored with the model state from before that target. Every bounded provisional candidate also predicts that target before incorporation, so later unseen evidence can replace a sparse-run winner instead of freezing the initial candidate. The target then enters provisional model and region statistics before Gazeebo selects the next target. The successful early-stop target and every final target-limit target enter the corpus before final fitting.

Each output has a normalized 3×3 region grid: four corners, four edges, and a center. Seeding visits cells in stable center/corner/edge phases across outputs and continues in later invocations when one invocation's target limit cannot cover every cell. A visited cell without pre-incorporation error remains explicitly uncertain and receives exploration; it cannot masquerade as a low-error cell. Inside a selected cell, a fixed-digit low-discrepancy sequence chooses a coordinate not previously used by the bounded scheduler sequence when one remains.

Each observed cell keeps a fixed-size exponentially decayed histogram. Every bin retains weight, squared weight, exact error sum, and exact squared-error sum. The scheduler walks the bins from highest to lowest and interpolates within the weighted 90th-percentile boundary bin so the selected tail contains exactly 10% of current weight. CVaR90 is that tail's weighted mean. Its expected surprise is CVaR90 plus median Bayesian predictive uncertainty, divided by the configured precision target. A one-sided confidence interval uses tail effective sample size and tail variance; bounded target noise widens the interval. Neither uncertainty nor noise gates collection or alters the target's positive model influence.

The production defaults fix the CVaR tail fraction at 0.10, decay derived regional evidence by 0.95 per subsequent observation in that region, divide the normalized range from 0 through 100 into 1,024 bins, and use the one-sided 95% normal quantile 1.6448536269514722. Values above 100 times the precision threshold enter the final bin. Expected surprise and its upper bound clip at 100 threshold units after adding bounded posterior uncertainty. Sparse cells use finite conservative uncertainty and variance priors; they never appear precise without observations. These limits affect only rebuilt scheduler summaries. Stored target error and uncertainty remain exact.

After seeding and uncertainty exploration, a cell is statistically dominant when its lower bound exceeds another cell's upper bound. Gazeebo selects the dominant cell with the highest upper bound and keeps measuring statistically high regions until all cell intervals overlap. It then balances tied cells by observation count, visit count, cell phase, and output order. Target choice uses no eventual target observation.

Reports combine each five consecutive pre-incorporation measurements and include selected cells, CVaR90, the highest pre-target surprise interval, observed-cell coverage, and 95th-percentile cursor spread without calling it measured pointer accuracy. Early stopping requires both accuracy gates, unseen evidence in every authorized cell, overlapping cell intervals, and every regional CVaR90 surprise upper confidence bound at or below the precision threshold. Equal regional costs above the threshold are not success.

For eight or more compatible targets, deterministic grouped folds hold every target out once and train on it in every other applicable fold. Fold results independently select bounded direct or frozen-neural feature subsets and Gaussian output-prior precision for the global fit and each sufficiently populated output fit. The nonlinear candidate uses one deterministic 48-unit head/face layer whose weights never train or grow; its Bayesian output layer still updates exactly from sufficient statistics. Gazeebo maintains fixed-dimensional weighted global, output, and held-out-fold natural parameters. It rebuilds region tail summaries during the same linear historical load pass. Each target updates one global, at most one output, and one fixed-size regional histogram in constant amortized work. Target selection scans at most nine fixed-size tail summaries on each of at most 16 outputs and performs a fixed-digit bounded target-sequence operation. Final candidate scoring and all-data posterior fitting take O(n) work for n targets when the configured feature, candidate, fold, context, output, and region bounds are fixed. The implementation does not rescan all earlier targets after a measurement, build pairwise target distances, or invert a sample-count-sized matrix.

The global and output posterior means map each observation or aggregate measurement vector directly to source-screen `(x, y)`. Output predictions are clipped to their own source regions before soft blending, and the complete mixture is mapped once into the current topology before authorized-union projection. New anchors retain coefficient covariance and finite residual variance for every component. These values and component disagreement yield predictive uncertainty without retaining target histories inside the model. More compatible evidence lowers uncertainty; high uncertainty slows navigation smoothing only when lower alpha bounds are configured and never rejects a target, triggers a retry, or removes influence. During active training, Gazeebo measures every raw posterior-mean mixture estimate and renders only the short median of those positions. The two-second window therefore captures high-rate estimation noise without spending time on cursor transit.

Gazeebo fits the selected posterior on every compatible historical and current target. Each target receives a bounded, strictly positive likelihood weight derived in part from its noise summary. Its feature dispersion also adds a bounded diagonal errors-in-variables term to the fixed-dimensional sufficient statistics, reducing sensitivity to noisy inputs without discarding the target. No five-target batch, recent window, or bounded coreset substitutes for the full compatible corpus.

Before activating a final all-data candidate, Gazeebo compares pre-incorporation target predictions and uncertainty with the incumbent over every unseen target in the invocation. The candidate may replace an incumbent only when it does not worsen aggregate median radial error, aggregate edge/corner error, worst output-cell median, worst regional CVaR90, or maximum regional surprise upper bound. Each accepted anchor records this validation target count. Complete-invocation anchors supersede nearby legacy anchors whose metadata covered only the final five-target report; context-diverse legacy anchors remain routable until complete evidence exists for their posture and lighting context. A new camera, context, or topology expert with no compatible incumbent may be established from a finite result. Reported metrics remain pre-incorporation or cross-validated evidence; Gazeebo never presents them as direct holdout accuracy for the final model that was subsequently fitted on all targets. A terminal precision miss may establish the first finite model so later invocations can improve it, but it remains below threshold and recommends more training. A rejected candidate leaves the prior model active while still retaining every newly completed target for future folds.

The default report size is five targets, the precision threshold is 100 logical pixels, and one invocation stops after at most 55 targets. It may stop earlier only when the latest unseen report's median and edge errors both meet the threshold, every authorized output cell has unseen evidence, no cell remains statistically above another, and every regional CVaR90 surprise upper bound meets the threshold. Repeated invocations resume missing or high-surprise regions while each transaction remains finite.

## Startup and lifecycle

Store loading, vision-model loading, portal authorization, and camera initialization run concurrently where ownership and toolkit constraints permit. Camera observations may supply passive context during the foreground invocation. No pointer message is sent until the portal has authorized pointer access, returned valid regions, and model routing has completed.

The active process owns its camera, RemoteDesktop and optional InputCapture portal sessions, EIS receiver, native surfaces, settle timers, live output monitor, model objects, and runtime socket. A permitted display-change pause closes that authorization epoch and reacquires all resources inside the same foreground invocation. Normal exit, errors, `SIGINT`, and `SIGTERM` close all of them through one idempotent path. The socket, refresh task, and training surfaces do not outlive the process.
