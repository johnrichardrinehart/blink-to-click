# Architecture

## Runtime boundary

`gazeebo` is one foreground process. Startup owns one camera, one desktop-portal session, the selected gaze models, an optional training surface and debug HUD, and an owner-only runtime control socket. Normal completion, `SIGINT`, `SIGTERM`, a portal-session closure, or an unrecoverable camera or store error runs the same idempotent cleanup path. No service, daemon, renderer, or worker process survives the executable.

The application separates hardware and desktop APIs from deterministic policy:

- `CameraCapture` owns a local camera and yields in-memory frames.
- `VisionEstimator` turns a frame into required head/face geometry, optional pupil refinement, and a pupil-independent posture and illumination context.
- `PointerController` exposes every portal-authorized display and region-local absolute motion. It has no button API.
- `DisplayMonitor` reads current logical output geometry through generic Wayland protocols without granting pointer access.
- Pure calibration, topology adaptation, context clustering, model routing, clipping, and smoothing components consume those interfaces.
- `TrainingStore` owns compact all-historical target aggregates, lossless encoding, read-only dumps, and atomic local updates.
- `StatusSink` reports state without coupling policy to a shell or graphical toolkit.
- `DebugHud` publishes opt-in, rate-limited diagnostics without changing navigation policy.

Tests replace every interface with an in-memory implementation. Camera devices, a graphical session, and user authorization are required only for explicit hardware acceptance.

## Camera and vision

OpenCV's [`VideoCapture`](https://docs.opencv.org/4.x/d8/dfe/classcv_1_1VideoCapture.html) API opens V4L2 capture devices and returns frames held in process memory. An explicit command-line device takes precedence. Automatic selection probes local capture devices and rejects sources that cannot return a frame; it does not encode a device path or product name.

[OpenSeeFace](https://github.com/emilianavt/OpenSeeFace) supplies the CPU face detector, 66-point landmarks, head pose, and pupil estimates. The package uses the pinned Nixpkgs derivation rather than downloading models at runtime, and imports the tracker in process instead of starting its UDP server. Camera transport is driver-selected by default; users may explicitly request YUYV or camera-encoded MJPEG. OpenSeeFace always receives decoded pixels. An explicit codec joins the negotiated dimensions in the opaque camera fingerprint, preventing calibration from crossing a transport boundary. Warning diagnostics still preserve the exact decoded frame supplied to detection losslessly, even when camera transport was lossy MJPEG.

The adapter requires one reliably bounded face with finite head pose. Its prediction features combine head pitch, yaw, roll, normalized face center and scale, explicit pupil availability/confidence, and pupil coordinates normalized within each rotated eye aperture when available. Eye-local normalization prevents head translation, face scale, and roll from masquerading as pupil motion. Feature-schema isolation retains older targets without interpreting their face-relative pupil coordinates as current eye-local evidence. Missing, closed, unstable, or low-confidence pupils use neutral pupil values plus an unavailable marker; they do not reject the frame. Context excludes pupil position so normal eye movement cannot switch experts. Frames and frame-level landmarks are discarded after each observation unless the frame falls inside an enabled sustained-warning diagnostic event.

When reliable head/face geometry is lost, inference stops cursor motion and pauses active measurement immediately. Tracking that recovers within 0.75 seconds resumes without presenting a sustained warning. A separate transient layer-shell surface shows the live local frame only after that confirmation interval, with face/head bounds where available, pose axes, a countdown, and corrective framing, scale, lighting, and focus guidance. The surface and pause last for a configurable minimum of 3 seconds by default so a brief tracking loss cannot flash unreadable guidance. Recovery resumes automatically after that interval once tracking is reliable. A separate configurable recovery timeout defaults to 10 seconds from initial loss, after which the diagnostic reports terminal failure and the process exits through shared cleanup.

A vision-estimator decorator keeps a three-second in-memory ring. After the 0.75-second false-alarm guard confirms a sustained warning, the default-enabled diagnostic archive coalesces overlapping warnings and atomically writes every raw detector frame from three seconds before through three seconds after the first trigger. One lossless event sequence stores the first frame exactly and each later frame as a bytewise XOR delta before whole-sequence gzip compression, exploiting similarity without adding a codec dependency. Stable JSON contains sequence indices, relative monotonic time, reason, confidence, bounds, pose, and all available landmarks. The normalized detector input is deterministic from the raw frame and is not duplicated. Completed event directories are owner-only and separate from training state. A 2 GiB quota disables new capture without evicting old events. Configuration or CLI can disable the decorator, in which case no archive is read or created. Estimator cleanup finalizes available event evidence and releases its active event and RAM ring.

## Authorized cursor motion

The [XDG RemoteDesktop portal](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.RemoteDesktop.html) is the pointer backend. Gazeebo requests pointer control, not keyboard or touchscreen control, and emits only `NotifyPointerMotionAbsolute`. It has no gesture recognizer, pointer-button API, click action, or evdev button mapping.

The request includes monitor sources from the [ScreenCast portal](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.ScreenCast.html), because absolute motion addresses an authorized stream. The portal returns one stream and property map per authorized display. `position` and `size` describe logical geometry; `logical_size` takes precedence when supplied. Multi-display sessions require stream positions so Gazeebo can reconstruct the authorized union. Opaque portal mapping identifiers become generic region descriptors when available.

Predictions inside an authorized region retain their global logical coordinate. Predictions outside the union, including desktop gaps, project to the nearest region edge and then convert to stream-local coordinates. Each raw reliable camera observation produces one estimated focal coordinate. A separate 15-position rolling median controls only the rendered cursor. Each 100-millisecond pointer update snaps to that robust rendered position with alpha 1.0 and a finite 10,000-pixel step bound; a noise-adaptive dead zone suppresses small jitter. Isolated prediction jumps cannot move a stable fixation, while sustained head or eye movement replaces the short position window within a few frames. Users may configure lower alpha or step bounds when they prefer animated transit. An interval of zero requests continuous updates.

Denied pointer access, incomplete geometry, malformed streams, or a closed portal session stops motion safely. Portal authorization and valid geometry are mandatory before the first pointer event. A process-scoped Wayland monitor checks available output geometry once per second by default. Additions trigger an in-process portal reauthorization pause unless the user disables it; disabling that pause keeps the old authorized union and cannot grant access to the new output. Removed or changed authorized geometry renews authorization or stops safely. Gazeebo never opens `/dev/uinput` or calls a compositor-specific output API.

## Rough-in and spatial refinement

A user-configured Return or key-sequence binding in an external keyboard layer sends an owner-only socket command. Gazeebo does not capture the key. Receipt of that command is the pinning boundary: gaze motion freezes at the latest authorized rolling-median estimate and the configured refinement flow starts. The process builds a component-wise confidence rectangle from compatible pre-incorporation evidence. Explicit finite width and height overrides take precedence independently. Otherwise the full width and height are twice the empirical p99 absolute horizontal and vertical residuals. Evidence resolves through the current normalized 3×3 training region, the output, and global compatible evidence. A level needs the configured sample minimum before it can claim component coverage. Sparse component evidence falls back through the same hierarchy to a conservative square based on legacy radial error, then to topology bounds. Fixed-size 1,024-bin histograms make construction linear in retained evidence and queries fixed-work. Output remapping scales horizontal and vertical residuals separately.

The rectangle stays centered on the rough point, caps its dimensions to topology bounds, and renders only where it intersects authorized output surfaces. Its status label reports evidence source, sample count, override or fallback, dimension clipping, and authorized-union intersection. A native transparent layer-shell surface on each output has an empty input region and no keyboard interactivity.

Refinement uses a bounded rectangular character matrix independent of the fixed 3×3 training-region scheduler. The default rows are `["123", "456", "789"]`. TOML `[refinement] rows` or repeatable `--refinement-row` arguments may replace the complete matrix with two through six equal-length rows of two through six columns. Every label is one distinct printable non-whitespace ASCII character. Configured labels replace numeric selection tokens completely. Each owner selection resolves its displayed character to a row and column, replaces the rectangle with that child, moves to its authorized-union-projected center, and redraws the same matrix recursively. Finite maximum depth and minimum cell dimensions prevent unbounded recursion. Matrix selection is spatial motion only and has no input-action semantics.

Accepting the matrix holds its projected center for optional manual adjustment. The final recursive rectangle follows each finite relative or absolute logical motion report while the process waits for settlement. One restartable timer retains only the latest point, hides the dynamic rectangle, and reports that point after 500 ms without newer motion. This transient point and all intermediate motion are excluded from target records, diagnostics, model fitting, and logs. Cancel releases the hold and resumes gaze navigation.

The optional XDG InputCapture path requests only pointer capability, installs compositor-validated zone-boundary barriers, connects a passive libei receiver, and binds only relative and absolute pointer motion. The portal cannot activate capture immediately; the compositor activates it after a barrier crossing. Buttons, keys, scrolling, touch, and gestures are neither bound nor handled. Unsupported capability, denial, missing barriers, or EIS disconnection is non-fatal and reports owner-socket motion as the portable fallback. The foreground cleanup path disables and closes InputCapture, removes the libei event source, closes refinement surfaces, cancels settle timers, and then releases the existing RemoteDesktop resources.

## Automatic training state

Gazeebo keeps one automatic local training store rather than exposing profiles. It persists every completed target aggregate until reset: median head/face and optional pupil features, robust per-feature dispersion, explicit pupil availability, posture and illumination context, output-relative true centers, finite cursor-noise summaries, optional pre-incorporation radial error, paired signed horizontal and vertical residuals, posterior uncertainty, and source topology. It also stores model parameters, aggregate validation results, and bounded accepted all-data model anchors. An anchor binds final coefficients refitted over all compatible historical and current targets to aggregate posture/position/illumination statistics without a name or timestamp. The store does not persist frames, images, raw landmarks, preparation observations, invalid partial windows, or per-frame cursor positions.

Version-nine persistence interns repeated descriptors, encodes records as compact arrays, and losslessly compresses the canonical payload. Version-nine targets may retain paired signed pre-incorporation component residuals. Version-eight and older targets remain exact and gain no fabricated components. Version-seven targets retain their exact errors and uncertainties but gain no fabricated CVaR validation results; version-six and older targets gain no fabricated surprise evidence. Atomic owner-only replacement and decompression limits remain enforced. `training-stats` reports storage cost; `dump-training` expands stable schema-labelled JSON to standard output without camera, portal, mutation, or a side file. A 10,000-target fixture enforces an average on-disk budget of 1 KiB per target.

The store supports an accepted global fallback, bounded accepted context experts, bounded per-output experts, and all-data training anchors. Online clustering groups compatible camera observations by posture, face geometry, and illumination. Cluster metadata may merge or evict, but target evidence never does. Every compatible target contributes to the global fit with a strictly positive bounded weight; output experts specialize without removing that global influence. Output/zone balance, context, pupil availability, and noise prevent one easy or recent group from dominating. Passive startup observations select or blend compatible accepted models and anchors by topology, then posture/camera geometry, then illumination and validation quality. Within each selected model, the global prediction supplies continuous geometry weights for at most 32 output experts. Local predictions are clipped to their source output and receive at most 80 percent total weight; the global model always retains at least 20 percent and gains all missing expert weight on sparse or added outputs. Navigation refreshes topology before its cached camera context at a configurable one-second default cadence; smoothed context routing and soft output weights prevent model-switch jumps. General mixtures fall back globally, while an anchor-only out-of-distribution route uses the nearest accepted camera context and reports low confidence.

Targets are stored relative to an output and can be remapped after unambiguous logical resolution, scale, or position changes. Validated global and per-output coefficient sets predict in their source geometry before one final mapping into the current topology, so a peer display change cannot compress the range of an unchanged display. Remapped target refitting remains the fallback when no safe coefficient mapping covers every current output. Removed-output samples are excluded while surviving outputs retain their validated prediction mapping. Added, sparse, or ambiguous outputs give their unavailable local weight back to the global/context fallback and use topology-bounds-normalized labels for best-effort navigation. Weak matches report inferred rather than measured quality. Every prediction still passes through authorized-union projection.

[`training.md`](training.md) specifies the schema, data minimization, topology matching, clustering, retention, model routing, and candidate acceptance rules.

## Initial and on-demand training

A first run without usable stored evidence enters initial training. Users can request more evidence with `gazeebo train`; they never name a profile. An active foreground process accepts the request through an owner-only Unix socket and transitions into training. If no process is active, the command owns a new foreground session. The socket is not a daemon and disappears on exit.

Every requested training invocation starts directly in the user's current output configuration, posture, camera geometry, and lighting. Those values contribute only aggregate unnamed context to completed target records and accepted anchors. Later routing combines compatible evidence without requiring a different state or exposing profile controls.

The native renderer creates one transparent overlay-layer surface per authorized output. Each surface spans only its output, has an empty input region, and requests no keyboard interaction. All surfaces show one invocation-level countdown and a direction cue before each target; then one surface draws the red circle while the others clear. The renderer obtains physical dimensions and the selected current pixel mode from standard Wayland output events only after an exact logical-geometry match. Policy converts one configured millimetre size per output and falls back to a configured logical-pixel diameter when metadata is absent or ambiguous. Five first-model seeds cross authorized outputs in stable order. A bounded region scheduler then chooses one output-relative 3×3 cell at a time, and a fixed-work low-discrepancy sequence supplies unseen positions inside that cell.

Every target starts with a configurable two-second preparation phase. The next red dot appears inside a square whose side equals the dot diameter while the prior dot overlaps and fades for one second by default. Direction cues remain visible across all outputs. The prior dot then disappears; the square remains until preparation ends and disappears when active measurement starts. Preparation is visual only.

Active measurement collects two seconds of reliable head/face observations by default. Pupil evidence refines each observation when available but never gates or restarts collection. Head/face loss pauses the measurement clock, retains the partial window, and invokes the bounded corrective diagnostic; recovery resumes the same target. Every reliable raw observation produces an estimated focal coordinate regardless of pointer-event cadence. Unseen error and the bounded cursor-noise summary use those raw estimates; the rendered cursor alone uses the 15-position median. Component-wise medians and median absolute deviations reduce the raw gaze and context window to one target record. Per-feature dispersion contributes a bounded diagonal errors-in-variables penalty to Bayesian sufficient statistics, while raw-estimate dispersion, covariance, and radial quantiles retain finite stationary-noise evidence without a trajectory. The same target record retains its pre-incorporation median radial error and median posterior uncertainty. Legacy records remain fitting evidence but do not gain invented unseen measurements.

Training reports total `collected / maximum` progress. Each target is selected from the current region state, predicted before it enters provisional training statistics, and immediately incorporated into both model and region statistics before the next selection. Each authorized output has a fixed normalized 3×3 grid. Seeding visits missing cells across outputs before exploitation and resumes across invocations. A fixed-size exponentially decayed histogram retains per-bin weight, squared weight, exact error sum, and exact squared-error sum. Explicit interpolation at the weighted 90th-percentile boundary estimates CVaR90, tail variance, and effective tail count. Bayesian uncertainty raises expected CVaR90 surprise, while bounded cursor noise widens one-sided confidence intervals. A cell is statistically high when its lower bound exceeds another cell's upper bound. The scheduler repeatedly selects the highest such bound and blocks dominated low-surprise cells until all intervals overlap, then balances tied cells deterministically. Sparse cells receive explicit uncertainty exploration rather than false low-surprise status.

Consecutive groups of five pre-incorporation predictions report hit rate, median radial error, edge/corner error, response time, 95th-percentile cursor spread, topology quality, expert routing, selected cells, CVaR90 surprise intervals, and observed-cell coverage. Reporting and early stopping remain batch-based. Early stopping also requires every cell to have unseen evidence, no statistically dominant high-surprise cell, and every regional CVaR90 surprise upper confidence bound at or below the precision threshold. Equal but excessive regional tails cannot stop training early. The successful early-stop target and every target-limit target enter the corpus before final fitting.

Deterministic grouped folds over every compatible target select Bayesian affine feature subsets, a bounded nonlinear head/face feature candidate, and prior precision for the global and applicable output fits. Each target is held out once and trains every other applicable fold. Noise may reduce a target's bounded likelihood weight but never to zero. Fixed-dimensional weighted moments are the posterior natural parameters shared by every bounded candidate. Global, output, and held-out-fold moments update in constant amortized work for each new target. Final scoring makes one linear pass over fixed candidates and outputs, then obtains each selected posterior from all-compatible-data moments. No best five-target sequence or recent window substitutes for the complete corpus.

New model anchors retain global and output posterior coefficient covariance and finite residual variance along with posterior mean coefficients. Repeated compatible evidence contracts predictive uncertainty near that evidence. Routing combines parameter uncertainty with output-mixture disagreement, and configured navigation smoothing becomes more conservative as uncertainty rises. Active training scores each raw posterior-mean estimate immediately and renders its short position median without animated transit, so cursor presentation cannot hide measurement noise or consume the fixed window. Uncertainty never gates collection, retries a target, or gives evidence zero weight. Older anchors without posterior or output-expert fields remain readable and use the existing global bounded-noise policy.

With feature dimension, candidate count, fold count, context-expert count, the 32-output expert bound, the 16-output scheduler bound, nine cells per output, and the tail-histogram size fixed, startup statistic construction, scheduler reconstruction, grouped scoring, and final fitting are O(n) in compatible target count. Each target updates one global, at most one output statistic set, and one fixed-size regional tail summary. Selection scans only bounded region and histogram tables and never scans historical targets. Incremental state and per-target work remain bounded apart from the required retained target corpus. Gazeebo does not rescan historical targets after each measurement, build pairwise target distances, invert a sample-count-sized matrix, or train new sample-count-sized kernels. Existing stored RBF anchors remain readable for migration. New fits use bounded Bayesian outputs over either direct features or a deterministic frozen 48-unit head/face layer. The hidden layer size never depends on target count, so it adds neural nonlinearity without replay, online forgetting, or sample-sized matrices.

Before activation, candidate and incumbent routing are compared over every current invocation target's pre-incorporation measurement. The candidate must not worsen aggregate median, edge/corner error, worst output-cell median, worst regional CVaR90, or maximum regional surprise upper bound. Persisted anchors record how many invocation targets supplied this evidence. A complete-invocation anchor supersedes nearby legacy anchors whose metadata represented only a final report, while context-diverse legacy anchors remain available until complete evidence replaces them. This preserves live routing between trained postures during migration. Reported unseen and folded metrics remain labelled as evidence for selection rather than direct holdout accuracy for the subsequent final all-data refit. A finite terminal result may establish a context that has no compatible model, remains below threshold, and triggers a training recommendation. Rejected candidates retain all new target aggregates for future folds while the prior model remains active. The default precision threshold is 100 logical pixels and the default hard limit is 55 targets per invocation, including first-run anchors. Training may finish earlier only when the latest five-target unseen report meets both error gates, all authorized output-cell intervals overlap, and every regional CVaR90 surprise upper bound meets the precision threshold. Timing, batch size, physical diameter, pixel fallback, threshold, limit, confidence level, decay, output count, and target-sequence bounds are finite validated settings.

## Development HUD

`--debug-hud` loads the packaged native renderer into the process and creates a transparent generic layer-shell surface. Refinement uses the same packaged renderer on separate transient surfaces even when the development HUD is disabled. An empty input region and disabled keyboard interactivity make it read-only and click-through. The renderer uses XDG Output to match global coordinates to generic output descriptions where available.

The HUD lists every authorized region, the current global logical X/Y coordinate, topology match quality, selected global/expert blend, selected training cell, CVaR90 and surprise interval, observed-cell coverage, active refinement matrix/pin/selection/settle state, and aggregate noise/smoothing class. It never displays stored feature values or trajectories. A one-second limiter prevents high-rate redraws. The HUD is disabled by default and destroyed through the shared cleanup path.

## Failure and privacy rules

The process reports loading, authorizing, selecting-model, topology-unvalidated, initial-training, countdown, target preparation, active target measurement, head recovery, diagnostic capture/quota state, adaptive-training, validating, all-data-refitting, active, noise-model selection, display-change reauthorization, truthful training completion, training-recommended, stopped, and concrete camera, portal, model, store, or training failures. Missing or stale frames, unavailable confident face observations, invalid geometry, closed authorization, and unsafe store or diagnostic state stop or suspend motion rather than producing guesses outside the authorized union.

All processing remains local. The application has no telemetry, cloud client, or continuous/untriggered recording. The XDG training store contains only finite compact target-level aggregates and protected model state. Every aggregate is retained until reset, so storage grows with training while descriptor interning and lossless compression keep it small. Its directory and file are owner-only; updates are atomic. `gazeebo reset-training` removes it, while ephemeral mode neither reads nor writes it. The separate default-enabled diagnostic archive contains only bounded warning events, remains owner-only and local, never enters training dumps or fitting, and persists until `gazeebo reset-diagnostics`.

## Reproducible packaging

The root flake exports the Gazeebo package and app for `x86_64-linux`. Its explicit fileset contains only runtime source, metadata, documentation, and tests. Nixpkgs supplies Python, dbus-next, NumPy, OpenCV, ONNX Runtime, OpenSeeFace, Wayland, Cairo, and Pango. Development formatters, hooks, type checking, and CI inputs remain in the `dev` flake partition.

Authoritative checks run deterministic tests, package/import checks, formatting and linting, strict type checking, and source-policy checks. Portal, camera, physical topology, posture, illumination, and target accuracy remain explicit hardware acceptance work because a sandbox cannot provide those observations.
